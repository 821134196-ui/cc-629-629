# 社区老人助餐资格变更与餐补结算系统

面向社区老年食堂的助餐补贴系统。核心解决一个问题：**老人资格会暂停/恢复，补贴必须按「实际就餐当天」的资格逐餐计算，而不是月底统一套用老人当前状态。**

## 一条命令启动

```bash
./run.sh
# 打开 http://localhost:8080
```

脚本会：构建 Vue 前端 → 构建 Go 后端（前端产物内嵌进二进制）→ 启动服务。
首次启动空库会自动写入演示数据（王秀兰 C001：9 月生效、10-10 暂停、10-20 恢复；李建国 C002）。

环境变量：`ADDR`（默认 `:8080`）、`DB_PATH`（默认 `backend/data/mealsubsidy.db`）、`NO_SEED=1`（不写演示数据）。

技术栈：Go 1.22 + Gin + GORM + SQLite（金额以「分」存储），Vue 3 + Vite，身份核验与支付为本地确定性模拟（无外部依赖）。

## 业务规则与设计要点

| 规则 | 实现方式 |
|---|---|
| 补贴按就餐日资格计算 | 资格是带 `effective_date` 的时间线；取 `effective_date <= 就餐日` 的最新一条。月底/以后的状态变化永不影响历史餐次 |
| 逐餐核销、保存当时资格 | `meals` 表在核销瞬间固化资格快照（状态、等级、补贴标准、依据登记 ID/日期、文字化计算依据）及补贴/自付金额 |
| 每餐可查补贴与依据 | 「老人就餐与补贴明细」页与结算单明细均展示每餐补贴及计算依据句子 |
| 重复扫码只核销一次 | `(老人, 就餐日, 餐次)` 唯一索引 + 事务内先查后插，重复扫码返回原记录并标记 `duplicate`，不产生第二笔流水 |
| 月结前发现登记错误 | 「封账前重算」：按最新登记重算区间内**未封账**餐次；旧补贴流水置 `voided` 留痕，追加新版本流水（餐次版本号 +1） |
| 封账固化 | 月结单金额封账时固化，已封账餐次被重算跳过；月份不可重复封账 |
| 封账后发现错误 | 只能**追加补差单**：逐餐列新旧补贴、差额、新旧依据、受影响日期清单；原结算单与原餐次快照一律不变 |
| 连续多次更正 | 补差单按「既往已调整差额」做增量，既不重复补差，也支持同月多轮更正 |
| 可对账 | 补贴流水（`ledger`）只追加；对账接口逐笔勾稽：餐次表合计 = 有效流水、封账金额 = 固化流水、补差单合计 = 调整流水、净应付 = 原结算 + 调整 |

数据模型见 `backend/internal/model/model.go`：老人、资格时间线、餐次（含快照）、月结单、补差单（含逐餐条目）、补贴流水。

## 页面

1. **老人与资格登记**：登记老人；维护生效/暂停/恢复时间线（支持补录历史日期、更正、删除）。
2. **食堂扫码核销**：选老人或输卡号 + 就餐日期/餐次/餐价；本地模拟核验与支付；展示当日资格快照、补贴、自付、依据、模拟流水号。
3. **老人就餐与补贴明细**：按月列出每餐补贴、自付、资格状态、版本号、计算依据。
4. **月结 / 重算 / 补差 / 对账**：封账前重算区间餐次；封账；封账后出具补差单（含受影响日期与逐餐新旧依据）；对账勾稽结果与净应付补贴。

## API 摘要

```
POST   /api/seniors                         登记老人
GET    /api/seniors                         老人列表
GET    /api/seniors/:id/status              当前状态（仅展示用）
POST   /api/seniors/:id/eligibility         新增资格登记（生效/暂停/恢复）
GET    /api/seniors/:id/eligibility         资格时间线
PUT    /api/eligibility/:rid                更正资格登记
DELETE /api/eligibility/:rid                删除资格登记
POST   /api/canteen/verify                  扫码核销（幂等）
GET    /api/seniors/:id/meals?period=       餐次明细
POST   /api/seniors/:id/recalc              封账前重算未封账餐次
POST   /api/seniors/:id/settlements         月份封账
GET    /api/settlements[?senior_id=&period=]
GET    /api/settlements/:id                 结算单 + 逐餐 + 补差单
POST   /api/seniors/:id/adjustments         封账后补差单（只追加）
GET    /api/adjustments[?senior_id=&period=]
GET    /api/seniors/:id/reconcile?period=   对账勾稽
```

## 验证

```bash
# 1) 单元/集成测试（7 个场景，内存 SQLite）
cd backend && CGO_ENABLED=1 go test ./... -v

# 2) HTTP 端到端冒烟：临时库真实起服务走完全链路
bash backend/scripts/smoke.sh
```

测试覆盖：

- **跨月资格按就餐日生效**：9 月生效 8 元 → 10-10 暂停 → 10-20 恢复 10 元，全部在之后核销，逐餐补贴为 800/800/0/0/1000，含补贴封顶餐价、无登记全自付；
- **幂等核销**：重复扫码返回同一记录、仅一条补贴流水，同天不同餐次各自核销；
- **封账前重算**：仅改未封账餐次、跳过已封账餐次、旧流水作废留痕、原结算不变；
- **封账后补差**：拒绝重复封账与重算已封账餐次；补差单列清受影响日期与新旧依据，原结算 2400 与餐次快照保持不变，调整流水 -1600 只追加；无差异拒绝出单；
- **跨月对账**：9 月 800、10 月经重算后封账 1800、补差 +200，净应付 2000，全部勾稽项通过；
- **补贴下调重算**、**无资格全自付** 两个边界场景对账仍平衡。
